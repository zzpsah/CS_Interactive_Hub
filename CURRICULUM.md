## Visual teaching and animation standard

Every published or planned chapter should include a concept-specific visual teaching plan. For each important process or transformation, decide how a learner will see it happen—not merely read a paragraph about it.

Expected pattern, adapted to each topic:
1. Concise bilingual explanation.
2. Labelled animated diagram or visual trace showing the concept's state change.
3. Worked example with the current step/component/value highlighted.
4. Learner-controlled exploration (step, reset, toggle, or safe custom input where appropriate).
5. Short understanding check with meaningful feedback.
6. Study & Copy and revision material.

Use Log2Base2 as inspiration for animated concept explanation and step-by-step code walkthroughs, not as content to reproduce. Create original, locally hosted, accessible visuals. Keep shared navigation and design consistent while using different visual models for hardware, networking, number systems, memory and programming. All motion must respect reduced-motion settings and must not be the only way to access information.

### Visual implementation roadmap
- **Class 9, Chapter 1 — Computer Systems, Hardware & Memory:** prototype; interactive input-processing-output-storage demo exists, with architecture/IPO motion foundation. Audit and improve each core concept before marking visual coverage complete.
- **Class 9, Chapter 2 — Software and Operating Systems:** existing application-launch and boot simulators are available in the practical lab; next improvement is to bring a step-controlled OS/process-state visual into the main theory chapter and ensure language parity.
- **Class 9, Chapter 3 — Files and Folders:** folder-tree explorer, save-process trace, filename validation; next improvement is a true create/move/rename/delete sandbox with undo and bilingual parity.
- **Class 9, Chapter 4 — Internet and Cyber Safety:** step-through web-request path and scenario-based safety choices with feedback; expand bilingual content parity and accessibility QA.
- **Class 9, Chapter 5 — Algorithms and Flowcharts:** step-through compare-two-values trace and custom input; improve flowchart branching visualization and test equal/negative inputs.
- **Class 9, Chapter 6 — Data, Bits and Bytes:** interactive eight-bit toggle and binary-to-decimal addition trace; expand representations beyond unsigned 8-bit integers where syllabus and learner readiness warrant it.
- **Class 10, Chapter 1 — Networks and the Web:** animate a request and packets across client, router/server, then show response.
- **Class 10, Chapter 2 — Digital Safety:** build scenario-driven interactions with visible consequences and feedback.
- **Class 11, Chapter 1 — Number Systems and Binary:** animate place-value columns and bit changes during conversion.
- **Class 11, Chapter 2 — Computer Organisation and Memory:** visualize address selection, read/write, RAM vs persistent storage.
- **Class 12, Chapter 1 — Python Functions:** step through line execution, arguments, local variables and return values.
- **Class 12, Chapter 2 — Lists and Data Handling:** animate indexed access, insertion/deletion and before/after list state.
- Planned chapters should define their visual model before implementation begins, alongside syllabus accuracy and bilingual content checks.


## Shared chapter design system — mandatory for every chapter

Every chapter must inherit the same established visual language and learning affordances as Class 9 Chapter 1. This is a project-wide implementation rule, not an optional topic-level preference. Use the shared stylesheet and shared lesson patterns for the notebook-inspired Study & Copy area, coloured hierarchy, consistent heading treatment, accessible icons, explanatory callouts, bullets/lists, diagrams, interactive states, bilingual labels, responsive layouts, print and reduced-motion support. Topic-specific visuals and animations must differ when the concept differs, while typography, spacing, colour tokens, section framing, and study-note experience remain coherent. Do not mark a chapter complete because it has text and one animation. Inspect the rendered page against Chapter 1, check every control and notes section, and fix cross-chapter drift before adding more isolated features.
